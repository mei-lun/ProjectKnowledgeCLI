# 当前状态与路线图文档分层设计

日期：2026-08-12

## 目标

将项目文档分成“当前已经可用”“下一版本确定要做”“未来可能支持”三层，消除 README、历史审计和当前实现之间的状态冲突，并为后续开发提供稳定入口。

## 文档边界

| 文档 | 只记录 | 不记录 |
| --- | --- | --- |
| `README.md` | 当前版本、已完成能力、真实验证、快速开始、已知限制、文档导航 | 未实现功能的详细设计、历史审计全文 |
| `docs/next-version-plan.md` | 下一版本需求 ID、范围、验收标准、工作量、状态和明确非目标 | 无排期的长期设想 |
| `docs/future-features.md` | 长期候选能力、价值、前置条件、优先级和是否纳入承诺 | 当前已完成能力、下一版本执行细节 |

## 内容规则

1. 默认中文，以表格和短列表为主。
2. README 的完成状态必须能由代码、测试或 gardenserver 实际结果证明。
3. 下一版本目标为 `0.1.18`；本次文档整理作为 `0.1.17` 发布。
4. 下一版本只解决开发指导知识化闭环：MCP 可检索、真实增量验收、适配器解耦和结构化指导增强。
5. 未来特性不是承诺；只有移入下一版本计划后才进入实施。
6. 历史审计保留追溯价值，但 README 链接到最新复核段落，不以旧矩阵作为当前状态来源。

## 验收

- README 不再声称 CodeGraph 未接入，也不再将新知识目录写成 `docs/knowledge/generated`。
- README 有当前能力、验证数据和限制表。
- 下一版本计划中每项都有需求 ID、验收标准和工作量。
- 未来特性按近期候选、中期增强、长期方向和明确非目标分组。
- 三份文档互相链接，版本和 CHANGELOG 更新到 `0.1.17`。
