# 未来特性清单

> 本文件记录长期候选能力，不代表开发承诺。只有具备真实问题、前置条件和验收标准，并迁入[下一版本计划](next-version-plan.md)后才实施。

## 使用规则

| 规则 | 说明 |
| --- | --- |
| 候选不是承诺 | 写入本文件不等于确定开发 |
| 当前需求优先 | 本地建库、自动更新、开发指导闭环优先 |
| 证据驱动 | 迁入版本前必须有真实失败样本或使用场景 |
| 小版本交付 | 每次只选择少量可独立验收能力 |
| 默认本地安全 | 网络、模型和外部系统必须重新授权 |

## 当前明确非目标

| 非目标 | 原因 |
| --- | --- |
| 自动修改业务源码 | 知识库提供事实和指导，不代替编码代理 |
| 自动将生成内容标记 verified | 语义正确性需要审核 |
| 自研完整多语言代码图 | CodeGraph 已承担事实图职责 |
| 读取 CodeGraph 私有数据库 | 避免绑定内部格式 |
| 默认上传源码 | 违反本地优先和显式授权 |
| 为每个具体功能生成永久文档 | 长期粒度是功能类别和方法论 |
| 无评测地增加 daemon、向量或 UI | 必须由真实瓶颈驱动 |

## 候选迁移流程

```text
真实问题 → 失败样本 → 最小需求和非目标 → 正负验收
→ 依赖/风险/工作量 → 迁入下一版本 → 测试先行实施
```

新增候选至少填写 ID、价值、前置条件、风险和“迁入下一版本条件”。
